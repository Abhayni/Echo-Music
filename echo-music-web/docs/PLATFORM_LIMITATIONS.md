# Platform Limitations

- YouTube Data API v3 supplies music-category search metadata, not direct audio streams. Its official IFrame Player API can play visible video but cannot supply audio-only playback through Echo's shared HTML audio player. Echo does not redirect, embed a separate player, hide a YouTube player, extract audio, or simulate playback. Selecting a result searches enabled Audius, Jamendo, and Internet Archive sources and accepts only an exact normalized title-and-artist match with authorized audio; otherwise it reports “Audio playback unavailable.” A match plays under its actual provider metadata, with the YouTube metadata retained separately.
- Jamendo requires an API client ID and app eligibility. Its server adapter uses the official API, but no real client ID was supplied, so live search and playback remain unverified and Jamendo stays disabled until configured.
- SoundCloud's API terms prohibit an alternative on-demand service aggregating its user content with content from other services. Spotify's Developer Policy prohibits a product or service integrated with streams or content from another service. No written approval for this hybrid use was provided, so neither provider is called even if credentials are configured. SoundCloud application registration requirements are not bypassed.
- Audius official public track search and stream endpoints are enabled. Real search, playback, seek, pause, and resume were verified. Tracks with access conditions or `is_streamable=false` are excluded; only the official Audius stream endpoint is used.
- HTML5 audio plays Audius tracks, qualifying Internet Archive CC BY 4.0 recordings, configured Jamendo official streams, and user-selected local files. Archive playback requires explicit CC BY 4.0 metadata and a qualifying full-length file. Commercial hits may have no authorized recording; the app does not substitute a preview, scrape/extract streams, or simulate playback.
- Podcast searches are separately limited to licensed Internet Archive podcast items. Track metadata depends on provider file tags; when no per-track artist is supplied, the result is marked "Unknown artist" rather than borrowing a potentially unrelated compilation creator. Artist and album entities depend on provider metadata, and playlists are local.
- Background playback and Media Session features depend on browser, operating system, power-saving policy and user permissions. Restored playback may require a user gesture because browsers can block autoplay after reload.
- Internet Archive controls catalog/CDN availability and codec support; the app reports real file metadata and cannot guarantee every file plays in every browser.
- A browser cannot grant Android ringtone ownership.
- Native Bluetooth codec telemetry and USB DAC bit-perfect routing are unavailable; Web Audio routing is bounded by browser/OS support.
- Android ShazamKit/native audio processing is not the same as browser audio recognition. A separate authorised provider is required.
- Native Media3 background notifications and Android system media scanning are unavailable. Media Session API is the browser equivalent where supported.
- Browser downloads are subject to CORS, cross-origin storage, and provider terms. Offline cache cannot provide unrestricted Android background downloads.
- Listen Together is not simulated: a real backend room server, authentication, and protocol transport are required.
- Cast, OAuth integrations, Google Drive, Spotify, Last.fm, Discord, and AI providers require credentials and secure server endpoints.
